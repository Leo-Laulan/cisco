2. Role-Based CLI : Vues et Superviews (Module 5.2)

Permet de découper les droits selon les rôles métiers sans se limiter à la hiérarchie rigide des privilèges.

Règles reines des Vues et Superviews

  • Prérequis : aaa new-model doit obligatoirement être activé.
  • Création d'une vue : Router(config)# parser view NOM-VUE.
  • Superview : Contient des vues associées via la commande view NOM-VUE.
  • Règle d'exclusion des superviews : On ne peut pas assigner directement des commandes individuelles à une superview. Elle ne stocke que des vues existantes.
  • Indicateur visuel CLI : Dans la commande show parser view all, une superview est systématiquement désignée par un astérisque (ex: JR-ADMIN *).
  • Indépendance : Supprimer une superview ne supprime jamais les vues enfants qui la composent.

3. Syslog : Architecture, Format et Niveaux (Module 6.5)

Structure standard d'une ligne Syslog :

*Mar 1 00:02:59.451: %OSPF-5-ADJCHG: Process 99, Nbr 172.16.10.5 on Serial0/0 from LOADING to FULL

  • OSPF = Facility (le protocole ou module émetteur).
  • 5 = Severity Level (niveau de gravité).
  • ADJCHG = MNEMONIC (code d'événement unique).

4. Network Time Protocol - NTP (Module 6.6)

NTP synchronise l'horloge des périphériques. Une hiérarchie en strates (Stratum) de 1 à 15 définit la distance à l'horloge de référence.
  • Stratum 1 : Équipement directement synchronisé sur une horloge atomique/GPS (Stratum 0).
  • Stratum 2 : Équipement synchronisé sur un serveur Stratum 1.
  • Lecture de show ntp status :
    Si la sortie affiche Clock is synchronized, stratum 2, reference is 192.168.1.1, cela prouve que le routeur actuel est stratum 2 et que son serveur source est 192.168.1.1 (qui lui est donc stratum 1).

5. Sécurisation : AutoSecure, Resilient Config & SCP (Module 6.1 & 6.2)

Cisco IOS Resilient Configuration

Maintient une copie sécurisée en flash inaccessible par les commandes utilisateur standard :

  • secure boot-image : verrouille l'image Cisco IOS courante.
  • secure boot-config : verrouille le fichier de configuration de démarrage (running-config sauvegardée).

Cisco AutoSecure

Exécutable en interactif (auto secure) ou silencieux (auto secure no-interact). En mode interactif, il demande :

  • Le mot de passe enable secret.
  • Le texte de la bannière légale (security banner).
  • L'identification des interfaces connectées au réseau public (untrusted) ou privé (trusted).

Secure Copy Protocol (SCP)

Permet le transfert de configuration chiffré via SSH. Prérequis :

  • SSH activé et opérationnel sur le routeur.
  • Activation explicite : ip scp server enable.
  • Compte utilisateur local avec privilège 15.

7. Fondamentaux AAA & Architecture (Module 7.1 & 7.2)

  • Authentication : Valide l'identité du sujet (« Qui êtes-vous ? » via mot de passe, token, certificat).
  • Authorization : Détermine les droits et services accessibles (« Qu'avez-vous le droit de faire ? » ex: restreindre l'usage au seul protocole FTP ou à un jeu de commandes).
  • Accounting : Mesure et enregistre les actions (« Qu'avez-vous consommé ou tapé ? » pour l'audit et la facturation).
  • Différence login local vs aaa new-model : login local applique uniquement la base locale sans possibilité de chaîner des méthodes de repli. AAA autorise des listes ordonnées (ex: contacter le serveur TACACS+, et en cas de non-réponse, basculer sur la base locale).

Diagnostic des Faiblesses et Taux de Suspicion

Le système détecte les réussites potentiellement acquises au hasard : si un domaine présente des erreurs, toute bonne réponse dans ce domaine est requalifiée en « réussite suspecte » jusqu'à ce que la maîtrise soit totale.
